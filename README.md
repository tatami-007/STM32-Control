# STM32 电控考核

基于 STM32F103C8T6、TB6612 和 MPU6050 的电机控制工程，使用编码器测速，通过 VOFA+ 设置目标并查看数据。

## 功能

- PWM 正反转与调速。
- 编码器测速，PID 速度闭环。
- IMU 数据采集与姿态解算，输出角速度、角加速度和欧拉角。
- 角度 PID 外环配合速度内环，控制电机轴上雪糕棒的角度。

## 硬件接线

| STM32 引脚 | 连接 |
| --- | --- |
| PA0 / TIM2_CH1 | TB6612 PWMA |
| PB0 / PB1 | TB6612 AIN1 / AIN2 |
| PA6 / PA7 / TIM3 | 编码器 A / B |
| PB6 / PB7 / I2C1 | IMU SCL / SDA，AD0 接地 |
| PA9 / PA10 / USART1 | USB 转串口模块 RX / TX |
| PA13 / PA14 | ST-LINK SWDIO / SWCLK |

所有模块共地，TB6612 的 VM、VCC 和 STBY 需正确连接。IMU 固定在棒上，pitch 转轴与电机输出轴平行。

## 构建与烧录

开发环境为 Windows PowerShell，需要 CMake 3.22 及以上、Ninja、GNU Arm 工具链和 OpenOCD。

在工程根目录执行：

```powershell
.\tools\build.ps1 -Preset Debug
.\tools\flash.ps1 -Preset Debug
```

烧录使用 ST-LINK。构建产物为 `build/Debug/STM32_Control.elf`，将 `Debug` 换成 `Release` 可构建发布版本。工具路径不同，可用 `-ToolchainBin` 和 `-OpenOcdRoot` 分别指定编译器目录与 OpenOCD 根目录。

## 使用

上电后保持电机和 IMU 静止约 2 秒，等待 `READY`。程序不会自动启动电机。

VOFA+ 选择 **FireWater**，打开设备对应串口，设置为 **115200、8N1、无流控**。发送框追加 LF 或 CRLF；`q` 无需换行。

| 指令 | 作用 |
| --- | --- |
| `pwm:300` / `pwm:-300` | 正转 / 反转，约 30% 占空比，范围 −500～500 |
| `speed:3` / `speed:-3` | 设置目标转速，单位 RPM，范围 −30～30 |
| `z` | 将当前位置设为零点，立即启动 0° 保持；发送前把棒摆水平并保持静止 |
| `angle:5` / `angle:-5` | 设置相对零点的目标角度，范围 −60°～60°；需先发送 `z` |
| `q` / `0` | 停止电机 |
| `r` | 停机并重新初始化、校准 IMU；成功后重新发送 `z` |
| `v` / `p` | 显示 / 暂停连续数据，不影响控制 |

发送一条指令后，等收到提示再发送下一条。默认只显示提示文字，发送 `v` 才会连续输出数据。

### 换电脑后的启动顺序

程序已经保存在 STM32 的 Flash 中，正常换电脑、断电重连不需要重新编译或烧录。演示电脑准备完整的 VOFA+ 文件夹和 [CH340 官方驱动](https://www.wch.cn/downloads/ch341ser_exe.html) 即可。若 ST-LINK 同时承担板子供电，保留其供电连接；演示时不需要打开下载或调试软件。

| 顺序 | 操作 | 确认结果 |
| --- | --- | --- |
| 连接设备 | 保持原接线和供电，固定电机，让棒和 IMU 静止约 3 秒 | 上电不会自动转动 |
| 打开串口 | 选择设备管理器中的 USB-SERIAL CH340 对应 COM 口，使用 FireWater、115200、8N1、无流控，追加换行 | 新电脑的串口号可能不是 COM5 |
| 确认通信 | 发送 `q` | 收到绿色 `STOP`；蓝色发送记录不代表板子已回复 |
| 重新校准 | 发送 `r`，保持装置静止，等待约 3 秒 | 收到 `IMU READY; SET LEVEL THEN SEND z` |
| 开始保持 | 把棒摆水平并保持静止，发送 `z` | 收到 `ZERO SET; HOLD` |
| 查看曲线 | 发送 `v`，绑定 I0、I1 | 显示目标角度和实际角度；需要时将纵轴范围调整到包含当前数值 |

`READY` 只在启动时发送一次，串口连接较晚可能错过，不代表启动失败。发送 `q` 检查是否收到 `STOP` 即可确认通信。每次断电、复位或发送 `r` 后，角度控制都需要重新设零。

| 现场现象 | 处理方法 |
| --- | --- |
| 找不到 CH340 对应串口 | 检查 USB 数据线、USB 接口和设备管理器；缺少驱动时安装 CH340 官方驱动 |
| 拒绝访问、串口打不开 | 完整退出其他串口工具或另一份 VOFA；仍占用时拔插 USB 转串口模块，再刷新并选择串口 |
| 只有蓝色发送记录，没有任何绿色回复 | 检查串口号、连接状态及 115200 波特率；按板上 RESET 后等待约 3 秒，再发 `q`。仍无回复时检查板子供电、串口 TX/RX 和共地 |
| `IMU INVALID` 或 `IMU LOST` | 先发 `q`，检查 IMU 供电与接线，静止后发 `r`；仍失败时关闭电机电源，再断开全部板子供电，恢复供电后静止重试 |
| 收到 `ZERO NOT SET` | 将棒摆水平，发送 `z`，等待确认后再设置角度 |
| 有数据但电机不动 | I15 为 0 表示停机；角度保持需先发 `z`。有 PWM 输出仍不动时检查电机电源、TB6612 的 VM 和 STBY |

正常演示不操作 BOOT 跳线，不重新下载固件。需要恢复固件时使用构建与烧录章节的脚本，并确认 OpenOCD 显示 `Verified OK` 后才算烧录成功。

### 保持目标角度

按下表顺序操作，每次只发送一条指令，并追加换行。

| 操作 | 指令或回复 |
| --- | --- |
| 把棒摆水平并保持静止 | 此位置作为水平零点 |
| 设零并开始保持水平 | 发送 `z`，等待 `ZERO SET; HOLD` |
| 保持在相对水平 10° 的位置 | 发送 `angle:10`；另一侧可发送 `angle:-10` |
| 回到刚才设定的水平位置 | 发送 `angle:0` |
| 停止电机 | 发送 `q` |

需要查看曲线时发送 `v`，绑定 I0（目标角度）和 I1（实际角度）；发送 `p` 只暂停数据输出。

角度控制不需要先发送 `pwm` 或 `speed`。这两种指令会切换控制模式，退出角度保持；角度模式的 PWM 由 PID 自动计算。再次发送 `z` 会把当时的位置重新设为零点，回到原零点应发送 `angle:0`。

### 转速与 PWM

测速时先发送 `speed:3`，再发送 `v`，将曲线绑定到 I2（目标转速）、I3（实际转速）。`speed:20` 表示目标转速为 20 RPM，转速控制不需要先发送 `z`。

`pwm:300` 表示固定约 30% 占空比，`pwm:-300` 表示反转。连续转动前拆下轴上的木棒，避免 IMU 导线缠绕。I5 显示实际 PWM 输出，发送 `q` 停止。

## VOFA+ 数据通道

| 通道 | 数据 | 单位 |
| --- | --- | --- |
| I0 / I1 | 目标角度 / 实际角度 | ° |
| I2 / I3 | 目标速度 / 实际速度 | RPM |
| I4 / I5 | 累计编码器计数 / PWM 输出 | 计数 / −500～500 |
| I6～I8 | X、Y、Z 角速度 | °/s |
| I9～I11 | X、Y、Z 角加速度 | °/s² |
| I12～I14 | roll / pitch / yaw | ° |
| I15 | 控制模式：0 停机，1 PWM，2 速度，3 角度 | — |
| I16 | IMU 数据有效标志：1 有效，0 无效 | — |

数据约每 50 ms 发送一次。六轴 IMU 的 yaw 会漂移。

## 代码结构

```text
Core/
├── Src/
│   ├── main.c       # 初始化、串口命令与控制主流程
│   ├── motor.c      # PWM 与方向控制
│   ├── pid.c        # PID 计算
│   ├── mpu6050.c    # IMU 初始化、原始数据读取与零偏校准
│   └── ins.c        # 四元数与姿态解算
└── Inc/             # 配套头文件与 config.h
tools/               # 构建、烧录脚本
tests/               # 主机模型测试与 CubeMX 生成区校验
STM32_Control.ioc    # CubeMX 外设配置
```

`main.c` 的 `USER CODE BEGIN 3` 按收指令 → 读数据 → 角度环 → 速度环 → 发数据的顺序执行。CubeMX 生成的初始化代码保留在原位置。

## 参数与故障处理

- `Core/Inc/config.h` 中的 `ENCODER_CPR` 是输出轴一圈的四倍频计数。1:48 型号商品页标注 528 线，按输出轴单相脉冲数计算为 `528 × 4 = 2112`，尚未实测确认。`ENCODER_SIGN` 和 `ANGLE_SIGN` 决定计数与角度方向。
- PID 参数在 `main.c` 的 `USER CODE BEGIN PV`。速度环初值为 `25 / 80 / 0`，角度环为 `1.5 / 0 / 0.05`，按 P、I、D 排列。先整定速度环，再整定角度环。
- 控制名义周期为 20 ms，PID 使用实际时间间隔。PWM 最大占空比约 50%，电机换向等待 100 ms。
- 角度模式短暂读失败会暂停输出并重置 I2C，200 ms 内恢复就继续控制，保留零点。持续失联则停机；检查供电和接线后发送 `r`，成功后重新摆平、发送 `z`。

## 测试

```powershell
.\tests\run.ps1
```

需要 Python 和主机 GCC，可通过 `-Python`、`-Gcc` 指定路径。测试覆盖 PWM、速度环、角度环、IMU 故障恢复及串口指令。

主机测试用于检查控制逻辑，实际控制效果需在装置上验证。
