# STM32 电控第一次考核

STM32F103C8T6 + TB6612 + TT编码器减速电机 + 六轴IMU。
基础考核四部分均有对应软件实现。OLED和按键按使用者要求不实现。

## 快速使用

1. 固定电机外壳、固定IMU与棒的连接，确认驱动电源、STBY、共地。
2. `./tools/build.ps1` 编译，`./tools/flash.ps1` 烧录并校验。上电电机保持停止。
3. VOFA：FireWater、COM5（以实际端口为准）、115200、8N1、无流控。
4. 串口默认每秒发送20帧数据。发送 `p` 暂停数值，`v` 恢复，`q` 立即停机。
5. 正反转调速：`pwm:300` / `pwm:-300`，都追加换行。
6. 速度闭环：`speed:3` / `speed:-3`，追加换行，画I13目标和I14实际速度。
7. 把棒手动放到水平并静止；发送 `z`，看到 `HORIZONTAL ZERO SET; HOLD ACTIVE` 后进入0度保持。
8. 设置棒目标：`angle:5` / `angle:-5`，追加换行，画I11目标和I12实际角度。

**当前CPR=2112是未核实的输出轴每圈计数。未确认前RPM仅是估算值，不能据此宣称测速准确。**
参考仓库只含IMU/OLED，没有TT电机型号或编码器参数。确认方法见下文。

## 目录及学习顺序

| 文件 | 职责 |
|---|---|
| `Core/Src/main.c` | CubeMX初始化与三个周期任务，用户代码写在USER CODE区 |
| `motor.c/.h` | PWM、方向、换向停顿 |
| `pid.c/.h` | 通用PID、抗积分饱和、测量微分 |
| `imu.c/.h` | I²C读取、寄存器校验、静止零偏校准、错误恢复 |
| `ins.c/.h` | 参考实验室代码移植的Mahony四元数姿态与角加速度 |
| `axis.c/.h` | 输出轴投影角度，支持当前斜装IMU的单轴控制 |
| `control.c/.h` | PWM/速度/角度模式、目标命令、水平设零、数据输出 |
| `vofa.c/.h` | 串口中断收发、命令分行、FireWater帧 |
| `app_config.h` | 电机参数、轴向、PID初值和输出限制 |

先读motor和pid，再读control中的速度环，最后读角度外环。控制关系为：

```text
目标角度 → 角度PID → 目标RPM → 速度PID → PWM → TB6612/电机
                ↑                   ↑
        IMU输出轴投影角度      TIM3编码器RPM
```

这是角度位置保持装置，不是车轮平衡车。电机只能抵消绕输出轴的转动；任意方向的三维倾斜无法用单电机补偿。

## 接线与CubeMX

| STM32 | 外设 |
|---|---|
| PA0 / TIM2_CH1 | TB6612 PWMA |
| PB0 / PB1 | AIN1 / AIN2 |
| PA6 / PA7 / TIM3_CH1/2 | 编码器A/B（四倍频TI12） |
| PB6 / PB7 / I2C1 | IMU SCL / SDA；AD0接地 |
| PA9 / PA10 / USART1 | USB转串口RX / TX，交叉连接 |
| PA13 / PA14 | ST-LINK SWDIO / SWCLK |

保持当前已验证的供电/驱动STBY接法；所有模块共地。编码器信号电平必须符合MCU引脚输入规格。
SYSCLK=HSI8MHz，TIM2 PSC=7、ARR=999，PWM=1kHz；TIM3 PSC=0、ARR=65535。
IMU配置200Hz，控制周期10ms，测速用实际dt并对16位计数溢出作有符号差分。
`main.c`保留CubeMX生成的外设函数；USART1中断处理在`stm32f1xx_it.c`的USER CODE区。
CubeMX重新生成后检查仍调用HAL_UART_IRQHandler。

## 命令表

参数命令必须追加LF或CRLF。裸单字符指令可不加换行，接收空闲30ms后解析。
同时发送多个单字符时逐行发送（如`p\nz\n`），不要拼成`pz`。

| 指令 | 效果 |
|---|---|
| `q` / `0` / `stop` | 电机立即停止；q在未完成的输入行中也有效 |
| `p` / `v` | 暂停/恢复数值；CTRL状态仍每秒报告 |
| `pwm:300` | 开环正转30%PWM；负数反转，允许±500 |
| `speed:3` | 速度PID，目标3RPM；允许±30，无30秒或计数行程超时 |
| `z` | 关闭电机，约2秒静止窗口建立当前位置为零点，再保持0度 |
| `angle:5` | 角度外环+速度内环；目标相对水平零点5度，允许±90 |
| `d` / `hold` | 恢复已设定的0度保持；不会重新采集零点 |
| `h` | 停机，准备重新摆水平；之后发送z |
| `c` | 停机并重新采集IMU静止零偏 |
| `enczero` | 停机，清零累计编码器计数 |
| `cpr:2112` | 停机，修改每圈四倍频计数，4～1000000 |
| `sign:-1` | 停机，修改编码器方向（仅±1） |
| `axis:-0.051,-0.996,-0.074` | 停机，设置正PWM对应的陀螺旋转轴，之后重新z |
| `speedpid:15,40,0` | 停机，修改速度PID Kp,Ki,Kd |
| `anglepid:1,0,0.06` | 停机，修改角度PID Kp,Ki,Kd |

运行时参数保存在RAM，断电后恢复`app_config.h`默认值。不要把停止后的状态reason当成正在运行的故障。
`CTRL state=ANGLE`才表示角度控制正在运行；STOPPED时reason给出实际停机原因。

## VOFA通道

每帧 `imu:` 后22个数，单位明确，无需链接浮点printf。

| 通道 | 含义 |
|---|---|
| I0～I2 | 加速度X/Y/Z，g |
| I3～I5 | 角速度X/Y/Z，°/s；校准前为原始值 |
| I6 / I7 / I21 | roll / pitch / yaw，°；yaw为相对航向会漂移 |
| I8 / I9 / I10 | 输出轴角度° / 轴向角速度°/s / 水平零点有效标志 |
| I11 / I12 | 目标角度 / 实际输出轴角度，° |
| I13 / I14 | 目标速度 / 编码器实际速度，RPM（准确性取决于CPR） |
| I15 | PWM百分比，带方向正负号 |
| I16 | 模式：0停机、1开环PWM、2速度PID、3角度PID、4设零采样 |
| I17 | 编码器累计四倍频计数（已调整方向），不因停止而清零 |
| I18～I20 | 角加速度X/Y/Z，°/s²；角速度差分后100ms低通 |

VOFA加绘图控件并绑定通道；数据引擎出现数值不代表已添加曲线控件。
需要读状态时发p，避免状态被数值刷走。使用助手读取COM5前先关闭VOFA串口，两个程序不能同时占用。

## 参数确认与整定

### 编码器CPR

输出轴四倍频计数 = 电机轴编码器线数 × 4 × 减速比（资料定义为四倍频数时不要再次乘4）。
也可停止输出，发送enczero，在能安全手动转动的条件下测量输出轴准确一圈的I17绝对值。
不能硬掰减速齿轮；带IMU导线的棒不要直接作整圈测试。实测数值用cpr命令验证，再写入app_config.h。

### 方向与安装

当前`APP_ENCODER_SIGN=-1`，`APP_SHAFT_AXIS`来自之前当前安装的实际辨识。
正PWM时，I17应增加、I9应为正；若A/B接线改变，修正sign；若传感器换装，重新设置axis。
零点只是你摆放位置的参考，不会自动知道棒与模块的几何关系。

### PID

先速度环：角度模式停止，用低速正/反目标，整定速度Kp、Ki直到实际速度稳定跟踪。
再角度环：z建立水平，先±5度，再逐步扩大目标；降低角度Kp可减小过冲，增加Kd可提供阻尼。
角度PID输出限为±12RPM，速度PID输出限±50%PWM。参数是初值，不代表实际负载已整定。
角度误差小于0.5度且转速很小时暂停输出；这时不转是死区逻辑，不是状态停机。
静摩擦助力为10～40ms短脉冲，真正开始PWM输出后计时，编码器有进展后缩短脉冲。

## 保护及已删除的旧逻辑

- 保留q急停、串口溢出、明显编码器跳变、控制周期卡顿、姿态失效时的角度停机。
- 速度模式仅依赖编码器，IMU未校准不阻止基础速度测试。
- 持续最高输出且编码器无有效进展2.5秒时停止，避免持续堵转；停机reason可见。
- 不再有±20度角度停机、600计数总行程停机、速度30秒定时停止、上电自动试转和PCA辨轴流程。
- 不自动取消故障并反复启动；修复原因后由使用者重新发目标。
- 棒/导线真实活动范围仍由安装决定，允许的目标范围不代表导线可安全转到那个角度。

## 验证与提交

`./tests/run.ps1`运行主机测试（默认CLion捆绑MinGW gcc，可用-Gcc指定）。
测试包含PWM正反转/换向等待、编码器溢出测速、连续速度PID、角度跟踪/外壳倾斜、姿态失效、堵转、串口命令、Mahony解算和静止校准。
主机模型不等于真实电机验证；实机验收结果单独记录在[docs/VALIDATION.md](docs/VALIDATION.md)。
逐条验收、两个视频和最终压缩包要求见[docs/ASSESSMENT.md](docs/ASSESSMENT.md)。
提交前必须确认CPR并完成实机速度/角度整定。不能用“编译通过”代替视频要求。
